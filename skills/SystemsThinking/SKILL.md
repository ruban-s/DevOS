# SystemsThinking

## Why Structure Beats Symptoms

Patch the bug, retry the request, add one more check — and the same incident is back next sprint. Event-level fixes bounce off because the cause sits three or four layers down, inside the structure that keeps manufacturing those events. Second-order effects stay invisible too: the "fix" ships and either spawns a fresh problem or deepens the original one. Without a way to see structure, you patch symptoms indefinitely — and the lever that would actually move the system is almost never located where the pain shows up.

## What the Skill Does

Five workflows read a system from symptom down to source:

- **Iceberg** — walk a visible event down through patterns to the structure and mental models generating it
- **CausalLoop** — map the feedback loops driving the behavior (CLD)
- **FindArchetype** — name the known pattern in play and apply its canonical fix
- **FindLeverage** — locate the strongest of Meadows' 12 intervention points
- **ConceptMap** — Novak-style entity-relationship mapping of a domain

**Done means:** the generating structure is named (not the nearest event), the intervention point is identified, and at least one round of the intervention's own feedback has been traced — second-order effects surfaced before anything ships.

## Standing Axioms

A **system** is a set of elements interconnected so as to produce a characteristic behavior over time. Swap the elements and usually nothing changes; rewire the interconnections or the purpose and behavior shifts dramatically.

The skill operates on five axioms:

1. **Structure generates behavior.** A recurring outcome has a structural cause — it is not a string of coincidences.
2. **Events are visible; structure is not.** Naive analysis stops at the event layer. This skill keeps descending.
3. **The feedback loop is the basic unit.** Every persistent pattern instantiates one of a small handful of loop shapes.
4. **Real leverage is counterintuitive.** The obvious fix frequently makes things worse — policy resistance, shifting the burden, fixes that fail.
5. **Parts don't optimize.** Local optimization routinely degrades the whole; only the system improves.

## When to Reach for It — and What It Buys

**Reach for it when:**

- The same class of bug, incident, slipped deadline, or conflict keeps returning, and event-level fixes aren't holding
- A fix produced a fresh problem, or worsened the one it targeted
- An architecture, product strategy, org structure, or policy is about to be committed
- Systemic debugging is needed: distributed-system flakiness, performance cliffs, reliability decay, compounding tech debt
- Strategy work: where competition, demand, adoption, or resistance actually originate
- Policy, incentives, organization design — anywhere human behavior is an input
- A large intervention is pending — run the causal loop first; intended effects are never the only effects

**What it buys:**

- **Structural causes**, instead of blaming whatever the nearest event touched
- **Archetype recognition** — most organizational and technical pathologies match one of ~10 known patterns; naming the pattern unlocks its canonical intervention
- **A located leverage point** — Meadows' 12 levels, ordered: parameters are weak, paradigms are strongest. Knowing where to push is the whole game
- **A second-order preview** — causal loops simulate second- and third-order effects before the change ships
- **Fixes that stay fixed** — structural changes don't regress the way symptom patches do

**Default stance:** on anything with recurring behavior, organizational dynamics, or cross-component coupling at Extended+ effort, structural analysis isn't optional enrichment — it's how you find the fix that sticks.

## Quick Reference

- **5 workflows** — Iceberg, CausalLoop, FindArchetype, FindLeverage, ConceptMap
- **Iceberg layers, top to bottom:** Events → Patterns → Structures → Mental Models
- **Loop types:** Reinforcing (R) amplifies — exponential growth or collapse; Balancing (B) seeks a goal — stabilizing
- **Archetypes:** ~10 canonical patterns (Senge, Braun)
- **Leverage points:** 12 levels, parameters (weakest) up to paradigm transcendence (strongest) — Meadows

## Examples

**Example 1: Recurring incidents**
```
User: "we keep getting paged for the same class of timeout"
→ Iceberg workflow
→ Events: 6 pages in 3 weeks
→ Patterns: all during deploy windows, all touching payments service
→ Structure: auto-scaler cold-start latency > health-check timeout during deploys
→ Mental model: "deploys are safe if tests pass" — but health checks aren't in the test path
→ Fix is structural, not another retry
```

**Example 2: Strategy**
```
User: "why does adding engineers slow us down past team size 12?"
→ FindArchetype workflow
→ Match: "Limits to Growth" archetype
→ Reinforcing loop: more engineers → more output → more hiring
→ Balancing loop: team size → coordination cost → per-engineer output ↓
→ Canonical intervention: attack the balancing loop (coordination mechanism), not the reinforcing one (stop hiring)
```

**Example 3: Unintended-consequences preview**
```
User: "we're about to add a rate limit to stop abuse"
→ CausalLoop workflow
→ Build CLD of users, abusers, support load, legitimate traffic
→ Surface: balancing loop (rate limit ↓ abuse), reinforcing loop (rate limit → legit users retry → total load ↑)
→ Recommend: rate-limit per-identity with reputation scoring, not per-IP
```

## Gotchas

- **Descriptive, not prescriptive.** Structural analysis reveals; it does not decide what to build. Generate interventions with `BeCreative` or `FirstPrinciples`.
- **No loop, no system.** If you can't draw at least one feedback loop, you've mapped a parts list, not a system.
- **Don't shoot the model.** When a loop says something unwelcome ("the incentives cause this"), rejecting the diagram is the error. Sit with it.
- **Delays do the damage.** Many systemic failures trace to lag between action and feedback. Mark every delay explicitly on the diagram.
- **Soft variables are real variables.** Trust, morale, perceived safety — keep them in the model even though they resist measurement.
